# 配置参数详解

本文件汇总三个模块的全部配置参数。SKILL.md 中的工作流只列命令示例，具体参数含义和边界情况在这里查阅。

---

## 模块零：预检查参数

```bash
python SKILL_DIR/scripts/bankflow_precheck.py \
  --gl "序时账.xlsx" \
  --bank "银行流水.xls" \
  --bank-subject "1002"
```

| 参数 | 说明 |
|------|------|
| `--gl` | 序时账文件路径 |
| `--bank` | 银行流水文件路径 |
| `--bank-subject` | 银行存款科目代码前缀，多个用逗号分隔（默认1002） |
| `--gl-subject-col` | 科目代码所在列名（AI 查看列名后指定） |
| `--bank-subject-name` | 按科目名称过滤（如"银行存款"），用于无科目代码列的场景 |
| `--subject-split-char` | 科目代码列的分隔符（如编码="1002/xxx"时用"/"） |
| `--bank-header-row` | 银行流水表头所在行号（从1开始，用于跳过前置元数据行） |

### 设计原则

脚本只做数据探查，AI 做判断。脚本不猜测列名、不自动生成配置。所有列映射和模式选择由 AI 读取输出后决定。

### 脚本输出内容

**银行流水**：
- 文件格式（.xlsx/.xls）、总行数、列数
- 所有列名列表
- 前3行样本数据
- 借方金额合计、贷方金额合计
- 对方户名列非空率（如有）
- 银行账号列分布（如有）
- 非交易行提示（如有摘要含"期初余额/本日合计"等）

**序时账**：
- 文件格式、总行数、列数
- 所有列名列表
- 前3行样本数据
- 银行存款科目（1002开头）的行数、凭证数
- 借方/贷方金额合计
- 候选客商列诊断表：每个候选列在银行存款行和对方科目行上的有值数 + 样本值
- 银行账户分布（来自金融机构列/科目名称/其他账户标识列）

> 数据清洗由 AI 负责，脚本不自动清洗。如需去除非交易行或提取复合字段中的客商，AI 用 Python 另存清洗后的文件，再用清洗后的文件做核对。

## 模块一：流水合并

```bash
python SKILL_DIR/scripts/bankflow_merge.py --config merge_config.json --output 合并结果.xlsx
```

### 配置格式

配置是一个 JSON，所有参数都是**列表**，长度等于文件数。AI 读取每个文件表头后，按文件顺序将列名填入对应位置：

```json
{
    "file_paths": [
        "/path/to/工商银行.xlsx",
        "/path/to/招商银行.xlsx"
    ],
    "header_start_rows": [2, 5],
    "header_start_cols": ["A", "A"],
    "bank_names": ["工商银行", "招商银行"],
    "account_names": ["某某公司", "某某公司"],
    "account_numbers": ["3960xxxxx", "8951xxxxx"],
    "transaction_date_cols": ["交易时间", "交易日期"],
    "transaction_time_cols": ["", "交易时间"],
    "counterparty_name_cols": ["对方单位", "对方账户名"],
    "counterparty_account_cols": ["对方账号", "对方账号"],
    "summary_cols": ["摘要", "摘要"],
    "income_cols": ["转入金额", "收入"],
    "expense_cols": ["转出金额", "支出"],
    "balance_cols": ["余额", "余额"],
    "skip_footer_rows": [0, 1]
}
```

### 参数说明

所有参数都是列表，第 i 个元素对应第 i 个文件：

| 参数 | 必填 | 说明 |
|------|------|------|
| `file_paths` | 是 | 文件绝对路径列表 |
| `header_start_rows` | 是 | 表头起始行号（从1开始） |
| `header_start_cols` | 否 | 表头起始列字母，默认 "A" |
| `bank_names` | 否 | 银行名称，留空自动从文件名推断 |
| `account_names` | 否 | 银行户名 |
| `account_numbers` | 否 | 银行账号 |
| `transaction_date_cols` | 是 | 交易日期列名（必须与表头一致） |
| `transaction_time_cols` | 否 | 交易时间列名（如果有单独的时间列） |
| `counterparty_name_cols` | 否 | 对方户名/交易对手列名 |
| `counterparty_account_cols` | 否 | 对方账号列名 |
| `summary_cols` | 否 | 摘要列名 |
| `income_cols` | 是 | 收入金额列名（注意：不同银行叫法不同） |
| `expense_cols` | 是 | 支出金额列名 |
| `balance_cols` | 否 | 余额列名 |
| `skip_footer_rows` | 否 | 跳过尾部N行（汇总/统计行），默认0。读取文件尾部后判断 |

### 输出格式

统一12列标准化Excel：

| 列序 | 列名 | 说明 |
|------|------|------|
| 1 | 来源目录 | 文件所在目录 |
| 2 | 文件名 | 源文件名 |
| 3 | 银行名称 | 标准化银行名 |
| 4 | 银行户名 | 账户名称 |
| 5 | 银行账号 | 文本格式 |
| 6 | 交易时间 | YYYY-MM-DD HH:MM:SS |
| 7 | 对方账户 | 交易对手名称 |
| 8 | 对方账号 | 文本格式 |
| 9 | 摘要 | 交易摘要 |
| 10 | 收入金额 | 数字格式 |
| 11 | 支出金额 | 数字格式 |
| 12 | 余额 | 数字格式 |

### 智能表头处理

脚本内置智能表头读取，能处理：
- **多行合并表头**：自动检测合并单元格，将多行表头合并为一行
- **偏移表头**：有些银行流水前几行是元数据（账号、银行名称等），表头从第N行开始
- **列名映射**：AI 识别实际列名后填入配置，脚本按列名提取数据
- **尾部汇总行跳过**：AI 读取文件尾部后，通过 `skip_footer_rows` 指定跳过行数

## 模块二：流水核对

```bash
python SKILL_DIR/scripts/bankflow_reconcile.py config.json --output 核对底稿.xlsx
```

### 配置格式

```json
{
    "gl_config": {
        "序时账路径": "/path/to/序时账.xls",
        "日期列名": "凭证日期",
        "凭证号列名": "凭证编号",
        "科目代码列名": "科目编号",
        "科目名称列名": "科目名称",
        "摘要列名": "摘要",
        "借方金额列名": "借方金额",
        "贷方金额列名": "贷方金额",
        "对方科目列名": "对方科目名称",
        "银行科目代码": "1002",
        "交易对手列名": "往来单位名称",
        "账户列名": "银行账户编号"
    },
    "bank_config": {
        "银行流水路径": "/path/to/银行流水.xlsx",
        "日期列名": "交易时间",
        "摘要列名": "摘要",
        "收入金额列名": "贷方金额",
        "支出金额列名": "借方金额",
        "交易对手列名": "对方户名",
        "账户列名": "银行账号"
    }
}
```

### 序时账配置 (gl_config)

| 参数 | 必填 | 说明 |
|------|------|------|
| `序时账路径` | 是 | 序时账文件路径 |
| `日期列名` | 是 | 记账日期列 |
| `凭证号列名` | 是 | 凭证编号列 |
| `科目代码列名` | 是 | 科目代码列 |
| `科目名称列名` | 否 | 科目名称列 |
| `借方金额列名` | 是 | 借方/收入金额 |
| `贷方金额列名` | 是 | 贷方/支出金额 |
| `银行科目代码` | 是 | 银行存款科目代码，多个用逗号分隔。多账户场景精确到具体代码（见SKILL.md"范围对齐"） |
| `交易对手列名` | 否 | **直接模式**：银行存款行上的客商列。引擎直接读取该列值。优先使用 |
| `客商辅助项列名` | 否 | **拆分模式**：对方科目行上的辅助核算列（如"客户,供应商"）。引擎从对方科目行提取 |
| `公司列名` | 否 | 多公司场景的公司标识列 |
| `账户列名` | 否 | 银行账号标识列（多账户时按账号分组核对） |
| `摘要列名` | 否 | 摘要列 |
| `对方科目列名` | 否 | 对方科目列（仅用于核对底稿展示，不影响匹配逻辑） |
| `日期范围` | 否 | GL日期过滤，格式 `"2025-01-01,2025-06-30"`。银行流水只覆盖部分时段时使用 |
| `主体过滤` | 否 | GL主体过滤。格式 `"列名,值1\|值2"`（第一个逗号前是列名，之后是值，多值用 `\|` 分隔）。序时账含多主体但流水只有1个主体时使用 |

### 客商模式选择

| 模式 | 配置 | 工作原理 | 何时使用 |
|------|------|---------|---------|
| 直接模式 | `交易对手列名` | 引擎从银行存款行直接读取客商值 | **优先使用**，匹配率更高（实证：92.6% vs 78.5%） |
| 拆分模式 | `客商辅助项列名` | 引擎从对方科目行（应收/应付等）提取客商辅助值 | 仅当银行存款行无客商值时 |
| 两者都配 | 两个都填 | 直接模式优先 | 不推荐，按需选一个即可 |

### 银行流水配置 (bank_config)

| 参数 | 必填 | 说明 |
|------|------|------|
| `银行流水路径` | 是 | 银行流水文件路径 |
| `日期列名` | 是 | 交易日期列 |
| `收入金额列名` | 是 | 收入金额列 |
| `支出金额列名` | 是 | 支出金额列 |
| `交易对手列名` | 否 | 交易对手/对方户名列，强烈建议提供 |
| `摘要列名` | 否 | 摘要列 |
| `账户列名` | 否 | 银行账号列 |

### 从合并结果直接衔接核对

合并输出的标准12列文件可直接作为核对的银行流水输入。固定映射：

```json
{
    "bank_config": {
        "银行流水路径": "/path/to/合并结果.xlsx",
        "日期列名": "交易时间",
        "交易对手列名": "对方账户",
        "摘要列名": "摘要",
        "收入金额列名": "收入金额",
        "支出金额列名": "支出金额",
        "账户列名": "银行账号"
    }
}
```

### 核对底稿输出格式

**Sheet 1 - 核对摘要**：各账号匹配率统计（金额匹配率、条数匹配率）

**Sheet 2 - 核对明细**：左右对照明细
- 左侧：银行流水明细（交易时间、金额、对手、摘要等）
- 右侧：序时账明细（日期、凭证号、金额、客商、摘要等）
- 中间：核对结果（匹配编号、匹配类型、交易对手核对状态）
